# 면접 설명 정리

## 1분 소개

KIS AI 트레이더는 한국 주식 데이터를 기반으로 AI가 모의투자 판단을 보조하는 대시보드 프로젝트입니다.

단순히 자동매매를 구현하는 데 집중한 것이 아니라, AI가 왜 매수하지 않는지, 어떤 데이터가 부족한지, 장이 열리지 않는 날에는 왜 새 손익을 만들면 안 되는지처럼 사용자가 오해하기 쉬운 부분을 화면과 운영 로직으로 분리했습니다.

특히 실거래 전환은 모의 검증, read-only 조회, 수동 승인, 첫 주문 승인으로 나누고, 운영 측면에서는 heartbeat, watchdog, 오라클 재부팅 복구, 알림, 감사 로그 백업까지 체크리스트화했습니다.

## 백엔드 관점에서 설명할 점

- 데이터 수집, 판단, 리스크 게이트, 모의투자 기록, 운영 점검을 역할별로 분리했습니다.
- 실주문 가능 여부를 단순 플래그 하나가 아니라 검증 기간, 데이터 신선도, 수동 승인, 첫 주문 마커로 단계화했습니다.
- API 응답에는 `source`, `is_final`, `fallback_reason` 같은 설명 메타데이터를 포함해 프론트에서 오해 없이 표시할 수 있게 했습니다.
- 운영 점검 결과를 JSON/Markdown으로 남겨 장애 분석과 포트폴리오 설명이 가능하도록 했습니다.

## 프론트엔드 관점에서 설명할 점

- 첫 화면에서 모의자산, 손익, AI 결론, 검증 상태를 빠르게 이해할 수 있게 구성했습니다.
- AI 판단 화면은 결론보다 판단 근거와 부족한 데이터를 먼저 보여주도록 설계했습니다.
- 히스토리는 누적 손익과 하루 변화를 분리해, 휴장일이나 장중 평가가 확정 수익처럼 보이지 않게 했습니다.
- read-only 화면과 관리자 화면을 분리해 일반 조회 접근성과 운영 보안을 함께 고려했습니다.

## 어려웠던 문제와 해결

| 문제 | 해결 |
|---|---|
| 휴장일에도 수익이 생긴 것처럼 보임 | 휴장일은 새 기록을 만들지 않고 직전 거래일 fallback으로 표시 |
| 화면은 살아 있는데 엔진이 멈출 수 있음 | heartbeat와 stale 감지 시뮬레이션 추가 |
| 특정 종목 뉴스/차트 누락 | 종목별 freshness와 source metadata를 ops guard에 포함 |
| 실거래 전환 위험 | read-only, 수동 승인, 첫 주문 마커로 단계 분리 |
| 공개 GitHub 보안 | 운영 코드/키/로그 제외, 설계 문서 중심 공개 |

## 예상 질문과 답변

### Q. 왜 바로 실거래 자동매매로 가지 않았나요?

실거래 도메인에서는 기능보다 검증과 안전장치가 더 중요하다고 판단했습니다. 그래서 모의투자 성과, 데이터 신뢰도, read-only 검증, 수동 승인, 첫 주문 마커를 모두 통과해야만 실거래로 넘어가도록 분리했습니다.

### Q. AI가 너무 보수적으로 아무것도 안 사면 어떻게 하나요?

안 산 후보의 이후 수익률도 기록하도록 설계했습니다. 이를 통해 AI가 위험을 잘 피한 것인지, 좋은 후보를 놓친 것인지 구분하고 다음 판단에 반영할 수 있습니다.

### Q. 백엔드에서 가장 중요하게 본 것은 무엇인가요?

데이터의 출처와 상태를 숨기지 않는 것입니다. 같은 가격이라도 KIS 원천인지 fallback인지, 장중 값인지 마감 확정 값인지에 따라 화면 해석이 달라지기 때문에 API 응답에 설명 메타데이터를 포함하는 것을 중요하게 봤습니다.

### Q. 프론트에서 가장 신경 쓴 것은 무엇인가요?

사용자가 숫자를 오해하지 않게 하는 것입니다. 특히 누적 손익, 하루 변화, 장중 평가, 휴장일 fallback을 구분해 보여주는 데 집중했습니다.

### Q. 운영 관점에서 배운 점은 무엇인가요?

서버가 켜져 있어도 엔진이 정상 동작한다고 볼 수 없다는 점입니다. 그래서 패널 프로세스뿐 아니라 heartbeat, timer, 포트, 데이터 freshness, 로그 백업까지 함께 봐야 한다는 것을 배웠습니다.
