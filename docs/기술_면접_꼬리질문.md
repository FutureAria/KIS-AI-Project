# 기술 면접 꼬리질문

## 결론

이 프로젝트는 “자동매매를 만들었다”보다 “위험한 도메인에서 데이터 정합성, 설명 가능성, 운영 안정성, 보안 공개 범위를 어떻게 설계했는가”로 설명하는 것이 좋습니다.

## 백엔드 질문

### Q1. API 응답에 왜 `source`, `is_final`, `fallback_reason`을 넣었나요?

프론트가 같은 숫자를 다르게 해석해야 하기 때문입니다. 예를 들어 장중 평가와 마감 확정 기록은 같은 손익처럼 보이면 안 됩니다. 또한 KIS 원천값과 fallback 값은 신뢰도가 다르기 때문에 API에서 출처를 명시해야 UI가 사용자에게 정확히 설명할 수 있습니다.

꼬리질문:

- fallback 값이 있으면 매수 판단에 그대로 쓰나요?
- 장중 값과 마감 값의 DB/파일 저장 기준은 어떻게 나누나요?
- source가 섞이면 캐싱은 어떻게 하나요?

### Q2. 실거래 전환을 왜 여러 단계로 나눴나요?

실거래는 버튼 하나로 열면 위험합니다. 그래서 모의 검증, 실계좌 read-only 확인, 키 회전, shadow mode 리뷰, 수동 승인, 첫 주문 마커를 분리했습니다. 각 단계가 통과하지 않으면 주문 플래그가 열리지 않는 구조가 안전합니다.

꼬리질문:

- 첫 주문 마커는 왜 필요한가요?
- kill-switch는 어디서 검사해야 하나요?
- 매도도 똑같이 막아야 하나요?

### Q3. heartbeat와 watchdog은 왜 둘 다 필요한가요?

웹 서버가 살아 있어도 AI 판단 루프가 멈췄을 수 있습니다. heartbeat는 판단 루프가 최근에 돌았는지 확인하고, watchdog은 그 상태를 주기적으로 점검해 복구나 알림을 담당합니다.

꼬리질문:

- 프로세스는 살아 있는데 heartbeat가 오래되면 어떻게 처리하나요?
- watchdog이 중복 실행되면 어떤 문제가 생기나요?
- 장애 알림이 실패하면 어떻게 해야 하나요?

### Q4. 휴장일 손익 기록은 왜 조심해야 하나요?

장이 열리지 않은 날에 새 손익 기록을 만들면 사용자에게 거짓 수익처럼 보일 수 있습니다. 그래서 휴장일은 새 기록을 생성하지 않고 직전 거래일 기록을 fallback으로 보여주며, 그 이유를 명시해야 합니다.

꼬리질문:

- 긴 연휴에는 어떤 날짜를 source로 보여주나요?
- 월이 바뀌면 달력에서는 어떻게 처리하나요?
- 장중 snapshot과 마감 기록은 어떻게 구분하나요?

## 프론트엔드 질문

### Q5. AI 판단 화면에서 가장 중요한 UX는 무엇인가요?

결론보다 이유를 먼저 이해시키는 것입니다. 사용자가 “왜 매수하지 않는지”, “무슨 데이터가 부족한지”, “실거래가 잠겨 있는지”를 한눈에 알아야 합니다.

꼬리질문:

- 데이터 부족 상태를 어떻게 보여주나요?
- AI 신뢰도 점수를 그대로 크게 보여주는 게 좋은가요?
- 초보자와 관리자의 화면 정보량은 어떻게 나누나요?

### Q6. 손익 UI에서 가장 조심할 점은 무엇인가요?

누적 손익, 하루 변화, 장중 평가, 마감 확정 기록을 섞지 않는 것입니다. 숫자가 틀리지 않아도 기준이 헷갈리면 사용자는 잘못 이해할 수 있습니다.

꼬리질문:

- 빨간색/파란색만으로 충분한가요?
- 미확정 값은 어디까지 강조해야 하나요?
- 모바일에서는 긴 설명을 어떻게 줄이나요?

## 운영/보안 질문

### Q7. 공개 GitHub에 왜 코드를 올리지 않았나요?

이 프로젝트는 실제 운영 코드, API 키, 계좌 정보, 서버 경로, 로그가 섞일 수 있는 성격입니다. 포트폴리오에서는 구현 역량을 설명할 수 있는 아키텍처, API 계약, 트러블슈팅, 운영 체크리스트를 공개하고, 민감한 운영 코드는 제외하는 것이 안전합니다.

꼬리질문:

- 코드가 없으면 구현 역량을 어떻게 보여주나요?
- 공개 가능한 샘플 코드는 어디까지인가요?
- 민감정보 스캔은 어떻게 하나요?

### Q8. 오라클 서버 재부팅 후 무엇을 확인해야 하나요?

패널 서비스, reverse proxy, 수집 타이머, ops guard timer, 포트, 중복 프로세스, 디스크, 실거래 서비스 inactive 상태를 확인해야 합니다.

꼬리질문:

- systemd enabled와 active의 차이는 무엇인가요?
- 서비스는 active인데 API가 느리면 어떻게 보나요?
- 로그 용량은 어떻게 관리하나요?
