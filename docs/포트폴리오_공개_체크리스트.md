# 포트폴리오 공개 체크리스트

## 결론

이 저장소는 회사나 평가자가 프로젝트의 목적, 설계 방향, 문제 해결 과정을 이해할 수 있도록 만든 공개용 저장소입니다.

실제 운영 코드와 민감 정보는 공개하지 않는 것을 원칙으로 합니다.

## 공개 전 보안 점검

| 항목 | 상태 | 기준 |
|---|---:|---|
| `.env` 포함 여부 | 제외 | 환경변수 파일은 공개하지 않음 |
| 서버 접속 정보 | 제외 | IP, SSH 명령, 키 파일 이름 공개 금지 |
| 계좌 정보 | 제외 | 예시 계좌도 실제처럼 보이면 제외 |
| 실거래 설정 | 제외 | 주문 플래그, 승인 문구, 운영 값 공개 금지 |
| 운영 로그 | 제외 | IP, 토큰, 계좌, 내부 상태 포함 가능 |
| 핵심 코드 | 제외 | 공개 포트폴리오에서는 설계 설명으로 대체 |
| 운영 자동화 스크립트 | 제외 | 서버 경로, 알림, 내부 로그 구조 노출 가능 |
| 문서 | 포함 | 민감 정보 제거 후 공개 |

## 데모 링크 기준

현재 운영 링크를 공개 README에 직접 넣는 것은 권장하지 않습니다.

이유:

- 인증이 걸려 있어도 운영 상태가 노출될 수 있음
- 관리자 화면 또는 내부 API 경로가 추측될 수 있음
- 운영 중인 서버의 도메인과 보안 설정이 공개될 수 있음

대신 아래 방식이 안전합니다.

- 면접 시 read-only 데모 링크를 제한적으로 공유
- 화면 캡처를 개인정보/운영 정보 제거 후 첨부
- 공개용 더미 데이터 데모를 별도 배포

## GitHub 공개 원칙

공개 저장소에서는 “전체 구현 코드”보다 아래 내용을 보여주는 것이 더 안전하고 포트폴리오 가치도 높습니다.

- 어떤 문제를 해결하려 했는가
- 왜 이런 구조를 선택했는가
- 프론트에서 사용자가 무엇을 이해하게 만들었는가
- 백엔드에서 안전장치와 운영 구조를 어떻게 잡았는가
- 실거래처럼 위험한 기능을 어떻게 단계적으로 잠갔는가
- 장애와 운영 리스크를 어떻게 문서화하고 개선했는가
