# 이력서 프로젝트 요약

## 3줄 요약

- 한국 주식 데이터를 기반으로 AI의 모의투자 판단, 리스크 차단, 손익 히스토리, 운영 상태를 시각화하는 투자 보조 대시보드를 설계했습니다.
- 가격/뉴스/공시/수급/글로벌 지표의 출처와 신선도를 구분하고, 휴장일/장중/마감 기록을 분리해 사용자가 수익을 오해하지 않도록 개선했습니다.
- heartbeat, watchdog, 오라클 재부팅 복구, 알림, 감사 로그 백업, 실거래 전환 잠금 등 운영 안정성과 보안 공개 범위를 체크리스트화했습니다.

## 이력서용 한 줄

AI 투자 판단 대시보드에서 데이터 출처, 모의투자 검증, 리스크 게이트, 운영 복구 체크리스트를 설계해 자동매매 도메인의 설명 가능성과 안정성을 개선했습니다.

## 사용 기술

| 영역 | 내용 |
|---|---|
| Backend | Python, 데이터 수집/정제, 모의투자 기록, 운영 점검 스크립트 |
| Frontend | 대시보드 UI, 히스토리/AI 판단/운영 상태 화면 설계 |
| Data | KIS API 기반 시세 구조, 뉴스, 공시, 수급, 해외장 선행 데이터 |
| Ops | Oracle, systemd/timer, launchd, heartbeat, watchdog, alert/report |
| Security | read-only 공개 화면, 관리자 분리, 비밀값 비공개, 공개 범위 관리 |

## 내가 설명할 수 있는 성과

- 장이 열리지 않는 날에는 새 손익 기록을 만들지 않도록 히스토리 진실성 규칙을 정리했습니다.
- 화면이 떠 있어도 AI 판단 루프가 멈출 수 있다는 문제를 heartbeat와 watchdog 관점으로 분리했습니다.
- 특정 종목의 뉴스/차트가 누락되는 문제를 데이터 freshness 점검 항목으로 분리했습니다.
- 실거래 전환을 read-only, 수동 승인, 첫 주문 마커로 나눠 위험한 기능을 단계적으로 잠갔습니다.
- 공개 GitHub에는 운영 코드와 민감 정보를 제외하고, 설계 문서 중심으로 포트폴리오를 정리했습니다.

## 면접에서 연결할 CS/백엔드 개념

| 개념 | 프로젝트 연결 |
|---|---|
| API 설계 | 프론트가 오해하지 않도록 `source`, `is_final`, `fallback_reason` 제공 |
| 장애 대응 | heartbeat와 watchdog으로 프로세스 생존과 루프 생존 분리 |
| 데이터 정합성 | 휴장일/장중/마감 기록을 분리해 거짓 손익 방지 |
| 보안 | read-only 화면과 관리자 기능 분리, 키/로그 비공개 |
| 운영 자동화 | systemd/timer, launchd, 알림, 감사 백업으로 장기 운영 고려 |

## 주의해서 말할 점

- 실제 수익을 보장한다고 말하지 않습니다.
- 실거래 자동매매가 완전히 열린 상태라고 말하지 않습니다.
- 외부 키나 실제 실계좌 증적이 필요한 항목은 완료로 말하지 않습니다.
- 공개 저장소에는 실제 운영 코드가 아니라 설계/문서 중심으로 공개했다고 설명합니다.
