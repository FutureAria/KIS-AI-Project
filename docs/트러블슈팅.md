# 트러블슈팅

## 결론

이 프로젝트에서 중요한 트러블슈팅 방향은 “화면이 보인다”에서 끝내지 않고, 데이터 원천, 운영 프로세스, 히스토리 진실성, 실거래 잠금 상태까지 함께 확인하는 것입니다.

아래 내용은 공개 가능한 수준으로 정리한 문제 해결 기록입니다.

## 1. 주말/휴장일 손익이 있는 것처럼 보이는 문제

| 항목 | 내용 |
|---|---|
| 문제 | 장이 열리지 않는 날에도 히스토리에 숫자가 있어 실제 수익처럼 오해될 수 있음 |
| 원인 | 누적 손익과 하루 변화를 같은 방식으로 표시하면 휴장일에도 새 기록처럼 보일 수 있음 |
| 해결 | 휴장일에는 새 손익 기록을 만들지 않고 직전 거래일 기록을 fallback으로 표시 |
| 검증 | `trading_day`, `source_date`, `is_final`, `fallback_reason`을 응답에 포함 |

## 2. 자동매수 엔진이 꺼진 것처럼 보이는 문제

| 항목 | 내용 |
|---|---|
| 문제 | 화면에는 패널이 살아 있지만 판단 루프가 멈췄을 가능성이 있음 |
| 원인 | 웹 서버 생존과 AI 판단 루프 생존은 다른 문제 |
| 해결 | heartbeat를 별도 기록하고 stale 상태를 감지 |
| 검증 | 실제 운영 파일을 건드리지 않는 실패 감지 시뮬레이션으로 `loop_freshness` 감지 확인 |

## 3. 특정 종목 그래프가 보이지 않는 문제

| 항목 | 내용 |
|---|---|
| 문제 | 일부 종목만 차트가 비거나 오래된 값으로 보일 수 있음 |
| 원인 | 종목별 데이터 수집 대상 누락, fallback 데이터 누락, 캐시 문제 가능성 |
| 해결 | 차트 파일 최신성과 source 컬럼을 운영 점검 항목에 포함 |
| 검증 | 마지막 거래일 기준 누락/오래된 종목 목록을 리포트에 표시 |

## 4. 뉴스가 5분마다 갱신되지 않는 문제

| 항목 | 내용 |
|---|---|
| 문제 | 보유 종목인데 뉴스 refresh 대상에서 빠질 수 있음 |
| 원인 | 기본 관심 종목과 실제 보유/모의 포지션 종목 목록이 어긋날 수 있음 |
| 해결 | 보유/모의 포지션 종목도 뉴스 refresh 대상에 포함 |
| 검증 | 종목별 뉴스 freshness를 운영 점검에서 확인 |

## 5. 실계좌 조회 증적을 완료로 볼 수 없는 문제

| 항목 | 내용 |
|---|---|
| 문제 | read-only 조회 구조가 있어도 API 오류나 빈 row면 실거래 증적으로 보기 어려움 |
| 원인 | 증권사 API 시간, 계좌 상태, 주문내역 존재 여부에 따라 응답이 달라질 수 있음 |
| 해결 | 원본 응답은 저장하지 않고 마스킹된 샘플만 증적으로 남기는 구조로 분리 |
| 검증 | 잔고, 주문내역, 미체결/취소 가능 조회가 정상 응답할 때만 완료 처리 |

## 6. 오라클 서버 재시작 후 꺼지는 문제

| 항목 | 내용 |
|---|---|
| 문제 | 서버 재부팅 시 패널, 프록시, 수집 타이머가 꺼질 수 있음 |
| 원인 | 프로세스를 수동 실행하면 재부팅 후 복구되지 않음 |
| 해결 | systemd/timer 기반으로 active/enabled 상태를 점검 |
| 검증 | 재부팅 후 서비스, 타이머, 포트, 단일 프로세스 여부 확인 |

## 7. 로그와 증적이 사라지는 문제

| 항목 | 내용 |
|---|---|
| 문제 | 서버 장애 또는 실수로 운영 로그가 사라지면 사후 검증이 어려움 |
| 원인 | 로그가 서버 내부에만 있으면 서버 장애에 취약 |
| 해결 | 감사 로그를 외부 백업 목적지로 export하고 write/read/delete를 확인 |
| 검증 | 백업 bundle과 manifest 생성, 자동 백업 예약 상태 확인 |

## 재발 방지 원칙

- 화면 표시 문제는 API 응답 계약까지 확인합니다.
- 데이터 문제는 source와 collected_at을 함께 봅니다.
- 실거래 관련 항목은 자동 완료 처리하지 않습니다.
- 외부 API 키나 권한이 필요한 항목은 `외부 설정 필요`로 분리합니다.
- 장애를 고친 뒤에는 반드시 리포트와 문서에 남깁니다.
